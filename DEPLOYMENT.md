# Deployment guide (Render)

This project is built to run on a managed PaaS. The checked-in
[`render.yaml`](render.yaml) blueprint creates everything Render needs:

- a **web** service (gunicorn) with a health check at `/health`
- a **worker** service (`celery worker`)
- a **beat** service (`celery beat`, exactly one instance)
- managed **PostgreSQL** and **Redis**

Uploads go to S3-compatible object storage (S3 or Cloudflare R2), because a
PaaS filesystem is wiped on every deploy. Static files are served by Whitenoise
from the image.

## 1. Create the Render services

1. Push the repository to GitHub.
2. In the Render dashboard choose **New → Blueprint** and select the repo.
3. Render reads `render.yaml` and prompts for the values marked
   `sync: false`. Fill in the SMTP, M-Pesa, Google, bucket and admin values.
4. Set `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS` and `SITE_BASE_URL` after the
   first deploy, once you know the `*.onrender.com` hostname and custom domain.
   The platform hostname is added automatically, so the first deploy can boot.

Generate secrets with:

```bash
python -c "import secrets; print(secrets.token_urlsafe(64))"
```

`SECRET_KEY` is generated by the blueprint. `ADMIN_URL` should be an
unguessable path, e.g. `manage-<random-token>/`; `/admin/` returns a 404.

## 2. Production environment

Everything is set in the Render dashboard (never commit `.env`). At minimum:

```dotenv
DEBUG=false
SECRET_KEY=<long random value>
ALLOWED_HOSTS=<app>.onrender.com,www.example.com,example.com
CSRF_TRUSTED_ORIGINS=https://<app>.onrender.com,https://www.example.com,https://example.com
SITE_BASE_URL=https://www.example.com
ADMIN_URL=manage-<random-token>/

# TLS is terminated by Render's proxy.
USE_X_FORWARDED_PROTO=true
TRUST_X_FORWARDED_FOR=true
SECURE_SSL_REDIRECT=true
SESSION_COOKIE_SECURE=true
CSRF_COOKIE_SECURE=true
SECURE_HSTS_SECONDS=31536000
SECURE_HSTS_INCLUDE_SUBDOMAINS=true
SECURE_HSTS_PRELOAD=false          # only after every subdomain is HTTPS

# Managed services (injected by the blueprint).
DATABASE_URL=postgres://...
REDIS_URL=rediss://...

# Uploads must outlive the container.
USE_S3=true
AWS_ACCESS_KEY_ID=...
AWS_SECRET_ACCESS_KEY=...
AWS_STORAGE_BUCKET_NAME=...
AWS_S3_REGION_NAME=auto
AWS_S3_ENDPOINT_URL=https://<account-id>.r2.cloudflarestorage.com
AWS_S3_CUSTOM_DOMAIN=media.example.com
AWS_S3_ADDRESSING_STYLE=virtual

# Real email is required: verification links and staff 2FA codes go here.
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=smtp.example.com
EMAIL_PORT=587
EMAIL_HOST_USER=...
EMAIL_HOST_PASSWORD=...
EMAIL_USE_TLS=true
DEFAULT_FROM_EMAIL=Car Dealership <noreply@example.com>
DEALERSHIP_NOTIFY_EMAIL=sales@example.com

STAFF_2FA_ENABLED=true

# So production 500s are visible somewhere.
DJANGO_ADMINS=Ops <ops@example.com>
# or: SENTRY_DSN=https://...

# Optional client-side analytics (GA4). Leave blank to disable. Tracking is
# opt-in: the cookie banner must be accepted before gtag.js loads.
GOOGLE_ANALYTICS_ID=G-XXXXXXXXXX
# Only set this to false where analytics consent is not legally required.
GOOGLE_ANALYTICS_REQUIRE_CONSENT=true

# Optional search-console verification tokens (meta-tag contents).
# GOOGLE_SITE_VERIFICATION=your-google-token
# BING_SITE_VERIFICATION=your-bing-token

MPESA_ENVIRONMENT=production
MPESA_CALLBACK_URL=https://www.example.com/payments/mpesa/callback/
```

The rest of `.env.example` documents M-Pesa, SMS, captcha, chatbot and backup
settings. Anything left unset keeps its safe default.

When `DEBUG=false`, the security flags default to their safe values even if a
flag is forgotten, and the app refuses to boot with the placeholder
`SECRET_KEY`, an empty `ALLOWED_HOSTS`, or a `DATABASE_URL` that cannot be
parsed.

## 3. Pre-flight checks

Run these locally (or in CI) with a production-like environment:

```bash
python manage.py check
python manage.py check --deploy
python manage.py security_check
python manage.py makemigrations --check --dry-run
pip-audit -r requirements.txt
python manage.py test
```

`security_check` checks DEBUG, the secret key, hosts, HTTPS/HSTS, secure
cookies, CSP, staff 2FA, the email backend, the database engine, the backup
directory, the admin path, `SITE_BASE_URL`, the M-Pesa callback, shared Redis,
error reporting, object storage and Django's deployment checks. It exits
non-zero when something must be fixed, so it can gate a deploy pipeline.

## 4. Build, migrate and seed

Render runs the build command from `render.yaml`:

```bash
pip install -r requirements.txt
python manage.py collectstatic --noinput
```

The web service's pre-deploy command runs `python manage.py migrate` before
the new instance receives traffic. To create the first superuser, open a
Render shell on the web service:

```bash
python manage.py createsuperuser
```

Then open the staff panel and give every staff member a real email address
(Staff → Staff accounts). Accounts without an email skip the second factor, so
an address is what makes 2FA effective.

## 5. Process model

The blueprint starts three services:

```bash
# web
gunicorn config.wsgi:application --bind 0.0.0.0:$PORT --workers 2 --timeout 60

# worker
celery -A config worker --loglevel=info --concurrency=2

# beat (exactly one instance)
celery -A config beat --loglevel=info
```

`beat` drives the periodic jobs:

| Job | Schedule | What it does |
|-----|----------|--------------|
| `check-mpesa-payments` | every 10 minutes | asks Safaricom about pending payments |
| `send-lead-reminders` | daily at 08:00 | follow-up nudges and unowned-lead digest |
| `send-order-deposit-reminders` | daily at 08:15 | deposit reminders for pending orders |
| `send-booking-reminders` | daily at 08:30 | next-day service, test-drive and hire reminders |
| `backup-database` | daily at 02:00 | snapshots the database and prunes old copies |

Free Render plans may not include background workers, and free web services
spin down when idle. That silently stops reminders and backups; budget for
paid worker and beat instances. Never run more than one beat process.

## 6. Static files and uploads

Whitenoise serves `staticfiles/` from the web image using manifest storage, so
asset URLs are cache-busted. `collectstatic` must run during the build (the
blueprint does this).

Uploaded media must use object storage. With `USE_S3=true`, the default storage
is `storages.backends.s3.S3Storage`; `MEDIA_URL` points at the bucket's custom
domain. Set a bucket lifecycle/versioning rule so deleted or overwritten files
can be recovered. Serving static files from the bucket is optional and only
needed if you move to a CDN: set `USE_S3_FOR_STATIC=true`.

The Dockerfile is a development convenience only. `docker-compose.yml` runs
`runserver` with SQLite and no Celery; do not use it for production.

## 7. Backups and restore

Render's managed Postgres provides automated backups and point-in-time
recovery on paid plans. That is the primary backup. The daily Celery job also
runs:

```bash
python manage.py backup_db
```

On a PaaS, `BACKUP_DIR` is inside the ephemeral container, so treat the local
dump as a secondary copy only. When `USE_S3=true` the command uploads each
dump to `s3://<bucket>/<BACKUP_S3_PREFIX>/` automatically; set
`BACKUP_UPLOAD_TO_S3=false` to keep it local. Also rely on Postgres PITR and
test a restore before launch:

```bash
python manage.py backup_db --output /tmp/today.dump
```

SQLite is snapshotted with the sqlite3 backup API. PostgreSQL uses `pg_dump`
in custom format when the client is installed, and falls back to a gzipped JSON
dump otherwise. Restore a SQLite backup by stopping the app and replacing the
database file (keep a copy of the current file first). Restore a PostgreSQL
custom-format dump with `pg_restore`, a JSON dump with
`python manage.py loaddata <file>`, or use the managed snapshot from the Render
dashboard.

## 8. Security headers

`config/security_middleware.py` sends:

- Content-Security-Policy (tight defaults; allows the vendored assets, Google
  Fonts, and a captcha provider only when its site key is configured)
- `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`
- `Permissions-Policy` (camera/microphone/geolocation/payment disabled)
- `Cross-Origin-Opener-Policy` and `Cross-Origin-Resource-Policy`

CORS is **off** unless `CORS_ALLOWED_ORIGINS` lists exact origins. That is
deliberate: the site is same-origin, and a wildcard would let any page read
authenticated responses.

`/health` is exempt from the HTTPS redirect so Render's probe gets a 200 even
when it speaks HTTP internally. Client IPs are read from `X-Forwarded-For` only
when `TRUST_X_FORWARDED_FOR=true`, and django-axes is configured with the same
proxy count.

## 9. Dependency updates

`.github/dependabot.yml` opens weekly pull requests for Python packages and
GitHub Actions. CI runs `pip-audit` on every push, so a new CVE in Django,
Pillow or a payment dependency fails the build before release.

## 10. Go-live checklist

- [ ] Blueprint deployed; web, worker and beat are all running
- [ ] `DEBUG=false`
- [ ] Strong `SECRET_KEY` in the environment (not in git)
- [ ] `ALLOWED_HOSTS` and `CSRF_TRUSTED_ORIGINS` set to the real domains
- [ ] `ADMIN_URL` is not `/admin/`; `/admin/` returns 404
- [ ] HTTPS works; `SECURE_SSL_REDIRECT`, secure cookies and HSTS enabled
- [ ] `python manage.py security_check` exits `0`
- [ ] `python manage.py check --deploy` clean
- [ ] `pip-audit -r requirements.txt` clean
- [ ] `migrate` and `collectstatic` run on the release commit
- [ ] `DATABASE_URL` points at managed Postgres (not SQLite)
- [ ] `REDIS_URL` set; cache and Celery use it
- [ ] `USE_S3=true`; a test upload survives a redeploy
- [ ] SMTP tested (password reset + staff 2FA code arrives)
- [ ] Every staff account has an email; staff 2FA verified end to end
- [ ] Celery worker and beat running; the five jobs visible in logs
- [ ] Managed Postgres backup/PITR enabled and a restore rehearsed
- [ ] `GET /health` returns `200 {"status": "ok"}` through the proxy
- [ ] Monitoring/uptime check pointed at `/health`
- [ ] Error logging and alerts configured
- [ ] `GOOGLE_ANALYTICS_ID` set (optional) and events visible in GA4 Realtime
- [ ] Cookie banner appears on a fresh visit; Accept loads GA, Decline keeps it off
- [ ] `/robots.txt` and `/sitemap.xml` load over HTTPS with the production host
- [ ] Search-console verification tokens added if the site is being claimed
- [ ] DNS, SPF/DKIM/DMARC configured for the sending domain
- [ ] M-Pesa production credentials approved and callback registered
- [ ] No test/debug accounts or sample data remain

## 11. After deploy

- Watch the Celery logs for the first backup and reminder runs.
- Confirm static files and uploaded images load over HTTPS.
- Sign in as staff and confirm the 2FA email arrives.
- Check the admin (the URL is set by `ADMIN_URL`) is reachable only by
  superusers (the project's admin site enforces this).
- Rotate any credential that was ever used locally, and delete `.env` from any
  server or image that still has it.
